# 教学 Q&A 范例：自建代理复盘

## 背景
三天搭建 VPS 代理后，用户说"感觉没学到多少"。Hermes 改为导师模式，出三道题检测理解。

## 三道题

### Q1: 家里电脑 ping 通 VPS 但连不上，为什么？封锁在哪一层？
**用户答**："中间部分，要么 Cloudflare 要么 ISP"
**诊断**：方向对但不够精确。
**正确答案**：ISP 在路由层封了 TCP 但没封 ICMP。ping 走 ICMP（独立通道），TCP SYN 被运营商路由器丢弃。两个协议在路由器上分别处理。

### Q2: VLESS 和 Shadowsocks 通过 CF Tunnel，一个失败一个成功，核心差别？
**用户答**："Cloudflare 支不支持这个协议"
**诊断**：太表面。
**正确答案**：VLESS 有握手阶段（认证、加密协商、流控），cloudflared 缓存重组 WebSocket 帧打断握手时序。Shadowsocks 无握手，连接建立后直接发加密流，不受帧重组影响。

### Q3: 最大的知识盲区？
**用户答**："以前用机场/Clash 都是黑盒，现在才知道底层是 VPS-协议-ISP 博弈"
**诊断**：满分。从"别人打包好的应用"到"知道每一层在干什么"——这是工程师的成长路径。

## 教学效果
- Q1/Q2 答偏 → 指出精确答案 + 推对应知识卡片
- Q3 答对 → 表扬思维转变
- 后续 8 轮追问（WebSocket 是 TCP？UDP 伪首部？协议套娃？）说明用户开始主动思考底层原理

## 技巧总结
- 问题从"现象→原理→大局"三层递进
- 答偏了不打击，给精确答案 + 卡片引用
- 答对了真诚表扬——用户需要知道自己方向对
- 追问来自用户主动好奇时（非考试式），是教学效果最好的时刻
