# 双 AI 审计调研法

## 触发条件

涉及技术选型、框架对比、架构决策时触发。尤其是：
- 调研新工具/新框架（如记忆系统、向量数据库、Agent 框架）
- 决定"用什么方案"的决策
- 一个 AI 给出的结论看起来"太完整、太确定"的时候

## 核心原则

> **不是让 AI 替你相信，而是让多个 AI 互相审查，最后由实验决定。**

## 三步流程

### 第 1 步：Hermes 广泛调研 → 整理地图

- 广度优先：覆盖尽可能多的方案
- 输出：对比表格 + 初步结论 + 信息源
- **不要省略信息源**——这是后续审计的依据

### 第 2 步：另一个 AI 做技术审计

- 拿 Hermes 的输出给另一个模型（ChatGPT/Claude/Gemini）
- 要求：**查官方文档、识别版本混用、挑战结论**
- 重点排查：
  - 版本混用（旧版 API 混新版概念）
  - 语言方向错误（Python SDK vs TypeScript SDK 搞反）
  - 过度拔高（把一个基础设施能力说成哲学突破）
  - 过时信息（deprecated API、已移除的依赖）

### 第 3 步：实验裁决

- 不因"文档上看起来最好"就选型
- 用同一组测试数据跑不同方案
- 记录真实性能、准确性、易用性
- 用自己的实验结果做最终决策

## 适用边界

- ✅ 技术选型、框架对比、架构决策
- ✅ 开源项目评估（版本迭代快，文档容易过时）
- ❌ 不适用于：基础概念学习（直接看权威教材）、代码实现（直接测试）

## 实施经验

- 2026-07-30 记忆系统调研：Hermes 初版有 4 处重要错误（Letta 版本混用、Mem0 架构过时、LangChain API 过时、过度拔高 Dreaming），经 ChatGPT 审计后修正。初版方向判断仍有价值（Letta 方向对），但技术细节不可直接用于选型。
- 关键教训：当 Hermes 输出看起来"很完整很有说服力"时，正是最需要第二意见的时候。
