# 行业调研工作流 (Industry Research)

## 定位

本技能从 v2.0 起升级为 **四层投资决策系统**，对抗大模型天然的技术乐观偏差。

```
信息收集
 ↓
技术判断层   （技术是否可行？）
 ↓
产业结构层   （谁受益？）
 ↓
商业落地层   （谁真的赚钱？）  ← v2.0 新增
 ↓
资本周期层   （什么时候反映到股价？） ← v2.0 新增
 ↓
投资判断
```

**各版本新增的核心模块**（所有涉及投资结论的调研强制输出）：

| 模块 | 版本 | 解决的问题 | 对抗的偏差 |
|------|:---:|-----------|-----------|
| **Bear Case Analysis** | v2.0 | 如果逻辑错了，最可能错在哪？ | 确认偏误 |
| **商业落地六维评估** | v2.0 | 技术成立 ≠ 商业成立 ≠ 投资成立 | 线性外推 |
| **价值捕获分析** | v2.0 | 谁创造了价值 vs 谁捕获了价值？ | 受益者偏差 |
| **🔴 反向利益追踪** | **v3.2** | **每一轮涨跌，谁赚了钱？找到盈利者就找到了行情驱动力** | **受害者偏差——只分析"谁亏了"不分析"谁赚了"** |
| **🔴 地缘金融博弈** | **v3.2** | **汇率联动、定价权转移、跨境杠杆爆破——A股不是孤岛** | **孤岛思维——默认A股板块行情独立于全球资本博弈** |
| **🔴 全球联动检查** | **v3.2** | **分析A股板块时，韩国/日本/美股同期在发生什么？** | **近视偏差——只看本地数据不看全球联动** |

> 🔴 v3.2 核心洞察（2026-07-30 半导体调研教训）：每 1 元亏损必对应 1 元盈利。找到那个盈利者，就找到了行情的真正驱动力。韩国控制全球 79% HBM 供应——当韩国半导体暴跌同时 A 股半导体也暴跌，这不是巧合，地缘金融博弈才是底层逻辑。

### 模式 A：A 股/港股投资调研（主模式）
核心目标：判断一个行业板块未来 6-12 个月是否值得持续买入/持有。
→ 走 Kanban 多 Agent 流程（vb-researcher + vb-analyst + vb-librarian）

### 模式 B：产品/技术全品类调研（3 Agent 并行）

核心目标：全品类产品横评 + 技术路线对比 + 产业链分析 + 未来趋势预判。

**工作方式**：使用 `delegate_task` 并行分派 3 个 Agent：
- Agent 1：产品赛道 A（如 AI 音频眼镜 + MR 头显）
- Agent 2：产品赛道 B（如 AR 眼镜）
- Agent 3：产业链 + 市场规模 + 趋势预判

> 完整 Agent 任务描述模板见 `references/mode-b-agent-templates.md`（含产品调研模板 + 假设验证模板）

### 模式 C：Hermes 直做（单标的快速复核 / 技术周期映射）

核心目标：单标的或板块的快速 v3.0 复核，由 Hermes 直接完成全部五模块分析，不走 Kanban 多 Agent 调度。

**适用场景**（满足任一即可走模式 C，无需 Kanban）：
- 用户明确要求"快速复核"或"快速分析"
- 单标的/单 ETF 的 v3.0 五模块分析（如"宝信软件 v3.0 完整分析"）
- 技术浪潮的泡沫阶段判断、历史周期映射
- 验证特定投资假设（如"IDC 是否处于 🟢C 错位"）

**与模式 A 的边界**：
- 模式 A：板块级全景调研（需要行业背景+政策+估值+资金面+策略的完整章节，数据量大，需要多 Agent 分工）
- 模式 C：聚焦 v3.0 核心五模块（Bear Case / 价值捕获 / 六维 / 资本周期 / Cycle Mismatch），实时 API 拉数据 + 训练知识交叉验证，1 个报告文件直出

**数据获取优先级（模式 C）**：
1. **腾讯行情 API**（`qt.gtimg.cn`）——实时 PE/PB/市值，最快最稳定
2. **东方财富个股页**（`quote.eastmoney.com`）——browser_navigate 直接访问，抓取 PE(动)、F10 数据
3. **东方财富股吧**（`guba.eastmoney.com`）——browser_navigate 直接访问，获取市场情绪和近期讨论热点
4. **🔴 东方财富新闻搜索**（`so.eastmoney.com/news/s`）——当 1-3 全部不可用时（API 连接失败、个股页 JS 空白）：新闻快讯段落的涨跌幅/股价数字是唯一实时数据源。详见 `references/china-financial-data-fallback.md`
5. **用户提供数据**——如果用户提供了 PB/PE 分位数据，直接使用并标注来源
6. **训练知识**——行业背景、历史案例、竞争格局等定性判断

**蛋卷 API 不可用时**：PE/PB 分位数据优先让用户提供，或在报告中标注「蛋卷 API 403 拦截，分位数据暂缺，以下为趋势性判断」。

**框架和方法论**：详见 `references/technology-cycle-mapping-framework.md`

**数据获取**：当 Google/Bing 搜索不可用，优先使用 Wikipedia API 提取结构化事实数据，详见 `references/wikipedia-api-extraction.md`。

**🔴 金融搜索的 3-strikes 规则**：搜索投行研报/评级时，禁止在 2-3 次尝试后直接下结论"找不到"。正确顺序：
1. Sogou 搜狗网页搜索（`curl` + 关键词提取）
2. 东方财富研报中心个股页（`data.eastmoney.com/report/stock/<code>.html`）
3. 国内券商研报（中信/中金/华泰，覆盖远广于外资投行）
→ 3 轮均无结果后，告知用户"该标的无覆盖"并提供替代方案（国内券商、自行推算估值）。**不要**在第 1 轮失败后就说"研报是付费的所以搜不到"。

### 🔥 暗线挖掘（跨模式适用）

当进行投资方向挖掘时，重点寻找「市场还没把新技术当核心叙事、但逻辑最顺」的标的——详见 `references/dark-horse-mining.md`。

核心三步：
1. 找出「正在被迫降本」的行业（需求饥渴）
2. 找到「已经卡位」的平台型公司（市占率高、迁移成本高）
3. 验证「AI 溢价为零」（PE <30 或亏损、研报不提 AI、股价不由 AI 驱动）

典型案例：视源股份（PE 28，市占率 40%+，市场当它是教育硬件而非 AI 入口）。

## 工作流

### Phase 1：调度（Hermes → vb-orchestrator）

创建 orchestrator 任务时，必须在任务描述中明确：
1. 这是金融调研，不是技术项目
2. 只需分配 vb-researcher + vb-analyst + vb-librarian
3. 禁止创建 vb-gh-explorer 和 vb-architect 任务

```bash
hermes kanban --board venture create "<调研主题>" --assignee vb-orchestrator
```

### Phase 2：干预（如果 orchestrator 走了默认模板）

如果 vb-orchestrator 自动创建了 vb-gh-explorer 或 vb-architect 任务：
```bash
hermes kanban --board venture block <task_id> "金融调研不需要代码解剖" --kind needs_input
```

## 🔴 商业落地六维评估（v2.1 强制）

| 维度 | 评分(1-5) | 依据 | 当前阶段 |
|------|:---:|------|------|
| **技术成熟度** | | 技术上能否做到？产品是否可用？ | |
| **商业成熟度** | | 客户愿意为此付费吗？有付费证据吗？ | |
| **组织变革阻力** | | 替换现有方案的成本有多高？（人/流程/系统） | |
| **行业 beta** | | 行业本身在增长还是萎缩？未来 3 年增速？ | |
| **监管/政策阻力** | | 监管是催化剂还是阻碍？有明确的政策风险吗？ | |
| **竞争壁垒** | | AI 时代产品易复制——这个方向有护城河吗？（数据/渠道/网络效应/行业 know-how/资本壁垒） | |
| **综合落地可行性** | | **六维几何平均：√⁶(乘积)**。任一维 <2 则综合 ≤2。壁垒维 <2 意味「赛道正确但谁都能做，利润归零」。 | |

> ⚠️ v2.1 新增「竞争壁垒」维度。AI 时代最大的风险不是技术做不到，而是做到了但谁都做得到——缺乏壁垒的方向，即使六维中前五维都高，最终利润也会被竞争抹平。

## 🔴 资本周期分析（v3.0 强制）

### 当前阶段定位
- **本方向所处阶段**：萌芽 / 爆发 / 过热 / 出清 / 普及
- **阶段判断依据**（3-5 条具体信号）：

| 阶段 | 技术状态 | 市场叙事 | 资本行为 | 股价特征 |
|------|---------|---------|---------|---------|
| 萌芽 | 实验室阶段 | 「很酷」— 极客关注 | VC 早期 | 无实质业绩 |

### 备选：东方财富 API

**批量拉取（推荐，20+ 只股票时首选）**：
```bash
# ulist.np/get 端点：一次拉取所有 A 股，字段 ID 与 stock/get 完全不同
curl -s --compressed \
  "https://push2.eastmoney.com/api/qt/ulist.np/get?fltt=2&secids=1.688111,1.600588,0.002410&fields=f2,f3,f12,f14,f20,f23,f37,f48,f49,f115&ut=fa5fd1943c7b386f172d6893dbbdf45b"
```

**单股查询（回退方案，港股专用）**：
```bash
curl -s --compressed \
  "https://push2.eastmoney.com/api/qt/stock/get?secid=0.002241&fields=f43,f57,f58,f164,f167,f184,f185,f51,f52,f116"
```

⚠️ **关键陷阱：两个端点的字段 ID 含义完全不同！**
- stock/get：f164=PE(TTM)（需÷100），f184=营收增速，f185=利润增速
- ulist.np：f115=PE(TTM)（直接值），f48=营收增速，f49=利润增速

完整字段映射见 `references/eastmoney-api-fields.md`。

### 蛋卷基金估值 API（PE/PB 历史分位）

```bash
curl -s --compressed \
  "https://danjuanfunds.com/djapi/index_eva/dj?index_code=SH000991&day=1"
```

⚠️ **注意**：蛋卷 API 的 `index_code` 过滤参数实际无效——API 始终返回全部 63 个指数。必须从全量响应中查找目标指数。字段含义见 `references/danjuan-valuation-api.md`。

### 浏览器 vs curl 选择

- **API 直连**：始终用 `curl -s --compressed`（终端），不要用 `browser_navigate`。浏览器无法解码东方财富 API 的 gzip 压缩响应，会报 UTF-8 解码错误。
- **网页浏览**：仅用于需要交互操作或 JS 渲染的页面。
- **API 全部不可用时的回退方案**：详见 `references/browser-data-fallback.md`（腾讯行情 API、东方财富个股页、东方财富股吧的可用路径速查）。
- **🔴 终极回退——东方财富新闻搜索**：当 API + 个股页 + 搜索引擎全部不可用时，`so.eastmoney.com/news/s` 是最后的数据通道。新闻快讯片段包含涨跌幅百分比、个股价格等具体数字。详见 `references/china-financial-data-fallback.md`。

## 常见陷阱

### 陷阱 1：中国网络下 Bing 搜索金融内容被严重过滤（🔴 新增）

在境内网络使用 Bing 搜索金融/投资相关查询时，搜索结果几乎全为无关内容（音乐、百科、工具导航），不会返回有效金融数据。

**应对**：
- **不要** 依赖 browser_navigate + Bing 获取金融数据
- 估值/行情数据：直接 curl 东方财富 API 或蛋卷 API（见上方 L2 数据拉取指南）
- 行业新闻/政策：优先百度或雪球网页（browser_navigate 到具体 URL，而非搜索）
- API 调用始终用 `curl -s --compressed`，不用 browser_navigate

### 陷阱 2：网络搜索超时（国内环境 🔴 高频）

vb-researcher / vb-analyst 的 web_search 在中国网络下经常超时。Agent 会回退到训练知识撰写报告，自动标注 `[待验证]`。

**影响**：行业数据可能基于旧知识（截止约2025年初），实时政策/估值数据可能不准确。

**应对**：
- vb-analyst 优先用 API 拉实时数据（东方财富/新浪/蛋卷），不依赖搜索
- 验收时检查报告中的 `[待验证]` 标记数量——如果 >10 处，标记为"需二次验证"
- vb-librarian 汇总时应在 REPORT.md 添加「数据质量说明」段落

### 陷阱 8：蛋卷基金估值 API 在中国 IP 下返回 403（🔴 2026-07 确认）

蛋卷基金估值 API（`danjuanfunds.com/djapi/index_eva/dj`）对中国大陆 IP 返回 `403 Forbidden`，无法获取 PE/PB 历史分位数据。

**应对**：
- 回落方案 A：**腾讯行情 API** 可获取 PE(TTM)、PB、52周高低等实时估值数据，配合训练知识估计历史分位
- 回落方案 B：用户手动提供分位数据（如"PB 分位 9.12%"），在报告中明确标注来源为 `用户提供`
- 回落方案 C：东方财富网页抓取（`quote.eastmoney.com`），页面包含 PE/PB 及历史区间图形数据
- **不要** 反复重试蛋卷 API——403 是持续性的 IP 封禁，非临时故障
- 报告中必须标注 `蛋卷 API 被 403 拦截，以下估值分位数据来源为___ [待交叉验证]`

### 陷阱 9：百度搜索在境内触发频繁 CAPTCHA（🔴 2026-07 确认）

百度搜索金融/股票相关查询时频繁弹出验证码（`wappass.baidu.com/static/captcha`），browser_navigate + Baidu 搜索路径几乎完全封锁。

**应对**：
- **不要** 依赖 browser_navigate + 百度搜索获取金融数据
- 替代方案：直接 browser_navigate 到目标页面（如 `quote.eastmoney.com/sh600845.html`、`guba.eastmoney.com/list,600845.html`），跳过搜索引擎
- 股吧（guba.eastmoney.com）可以直接访问，适合抓取市场情绪和近期讨论热点

### 陷阱 7：东方财富 API 在中国代理环境下速率限制严重（🔴 新增）

在国内网络通过代理访问东方财富 push2 API 时，连续请求会触发严厉的速率限制，表现为：
- `ProxyError: Remote end closed connection without response`
- `RemoteDisconnected`
- 首次请求可能成功，后续快速失败

**应对**：
- **优先用 ulist.np 批量端点**：一次拉取所有 A 股（`secids` 逗号分隔），将 20 次请求合并为 1 次
- **逐只 stock/get 时**：间隔 ≥1.5 秒，实现 3 次重试 + 指数退避（2s/4s/8s）
- **如果连续失败**：等待 30 秒后重试，不要立即重试
- **港股用 stock/get 单独拉取**：ulist.np 对港股 secid（`116.` 前缀）支持不稳定，经常返回空数据
- 完整的估值数据拉取脚本模板见 `references/eastmoney-api-fields.md` 的端点对比速查表

### 陷阱 6：Google/Bing 搜索在境内环境不可靠（🔴 新增）

在中国大陆网络环境中，Google 搜索经常触发 CAPTCHA 拦截，Bing 搜索对金融/技术内容严重过滤。当常规搜索不可用时，Wikipedia API 是获取结构化事实数据的高效替代渠道。

**应对**：使用 Wikipedia API 提取技术条目的事实数据（市值、投资额、历史对比等），详见 `references/wikipedia-api-extraction.md`。

### 陷阱 3：browser_navigate 无法解码东方财富 API 响应（🔴 新增）

东方财富 push2 API 返回 gzip 压缩的二进制数据，browser_navigate 会报 `'utf-8' codec can't decode byte` 错误。

**应对**：始终用 `curl -s --compressed` 在终端中调用东方财富 API。不要用 browser_navigate 直连 API 端点。

### 陷阱 4：vb-librarian 卡片格式不合规（🔴 与 Venture Brain 陷阱6 同源）

vb-librarian 产出 DRBCV 卡片时，frontmatter 可能使用错误格式：

**❌ 错误（vb-librarian 实际输出）：**
```yaml
id: 20260728-card-01
title: 创新药板块估值框架
type: concept
tags: [创新药, 估值]
relations:
  - 20260728-card-02
```

**✅ 正确（DRBCV 标准）：**
```yaml
name: 创新药板块估值框架
type: discriminant
status: core
source: "[[A股创新药板块投资调研2026-07-28]]"
domain: 创新药投资
```

修复方法（详见 `references/drbcv-card-fix-pattern.md`）：
- 卡片 ≥5 张 → 用 `execute_code` 批量创建（所有卡片内容预置在 Python dict 中循环 `write_file`）
- 卡片 ≤4 张 → 逐张 `write_file`
- 每张卡必须含：类比栏（一句话比喻 + 生活映射表）+ ≥2 正例 + ≥1 反例 + wikilink 关系
- type 必须是 discriminant/anomaly/prediction/causal 四型之一，禁止 `concept`
- 创建后用 `execute_code` 验证所有卡片 frontmatter 格式合规

### 陷阱 10：海外投行对 A 股中小市值覆盖极窄（🔴 2026-07 确认）

野村证券和摩根士丹利等海外投行**确实不覆盖**大多数 A 股中小市值公司。这不是"搜不到"——是"真的没有覆盖"。

**已验证的覆盖门槛**（2026-07）：
- 海康威视（市值 3200 亿）→ 大摩覆盖 ✅
- 恒生电子（市值 414 亿）→ 无覆盖 ❌
- 视源股份（市值 233 亿）→ 无覆盖 ❌
- 金山办公 → 仅通过港股母公司金山软件(03888)间接覆盖
- 广联达 / 宝信软件 → 无覆盖 ❌

**应对**：
- 搜索前先判断市值：<1000 亿的 A 股标的，海外投行大概率不覆盖
- 不要在这类标的上反复尝试不同搜索引擎——不是搜索引擎的问题
- 替代方案：国内券商研报（中信/中金/华泰）覆盖更全，东方财富研报中心可直接搜索
- 在搜索报告中**最多尝试 3 轮**（Sogou → 东方财富研报中心 → 国内券商），3 轮无结果则明确告知用户"该标的无外资投行覆盖"

### 陷阱 14：东方财富 API/个股页/搜索引擎全部不可用时，新闻搜索是唯一通道（🔴 2026-07 半导体调研验证）

## 数源与参考规范（🔴 铁律）

### 数源优先级（5 级分层）

**每条数据必须标注优先级。高优先级数据可覆盖低优先级数据的结论。**

| 优先级 | 层级名称 | 典型来源 | 使用规则 |
|--------|---------|---------|---------|
| **L1** | 一手官方数据 | 国家医保局公告、CDE 审评数据、上市公司年报/季报、FDA 官方数据库、NMPA 公告 | 政策/审批类分析的主论证来源 |
| **L2** | 实时行情/API 数据 | 东方财富 K线 API、新浪行情 API、蛋卷基金估值 API、Wind 终端、同花顺 iFinD | 估值/资金面分析**必须基于此层**，禁止用 L5 模糊替代 |
| **L3** | 权威行业报告 | IQVIA、Frost & Sullivan、米内网、医药魔方、药智网、Insight 数据库 | 行业规模/管线数据的首选来源 |
| **L4** | 金融机构研报 | 券商研报（中信/中金/华泰等）、公募基金季报/半年报、保险资管报告 | 估值逻辑/行业观点的补充参考 |

> 🔗 顶级投行个股分析框架（野村/摩根士丹利）：见 `references/sell-side-research-frameworks.md`——ModelWare + Risk-Reward + 跨区域协同方法论，含与 v3.1.1 的映射关系和差距分析。研究个股时建议额外回答大摩分析师的 5 个核心问题。
| **L5** | 媒体/综合资讯 | 财新、第一财经、21世纪经济报道、雪球、东方财富资讯、微信公众号 | **仅作背景补充，不得作为主论证来源** |

### 引用硬性规则

1. **每个数据断言必须标注来源编号**（如 `[L1-1]`、`[L2-3]`），格式为 `优先级-序号`
2. **来源表放在文末**，字段：编号 | 来源名称 | URL/渠道 | 优先级 | 最后访问日期 | 引用内容
3. **L5 来源不得单独支撑关键结论**（如"创新药处于底部"不能只引用一篇雪球文章）
4. **估值/资金面数据必须来自 L2**，不允许用 L5 的"据媒体报道北向资金流入"等模糊描述
5. **匿名信源零容忍**：禁止"业内人士称""有分析认为""据了解"等无源表述
6. **数据冲突时**：高优先级覆盖低优先级。L2 API 数据 ≠ L3 报告数据时，以 L2 为准并标注差异
