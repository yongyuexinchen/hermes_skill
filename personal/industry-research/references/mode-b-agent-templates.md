# 模式 B Agent 任务模板

> 两个经过实战验证的 Agent 任务描述模板。直接复制、填空、分派。

---

## 模板 1：产品全品类调研（如智能眼镜 / 新能源汽车 / AI 手机）

### Agent 1 + 2：产品研究员（各负责一个赛道）

```
【任务】<行业名>全品类调研 - Part N：<子赛道名>

【覆盖范围】
- 品牌 1：需收集的参数项
- 品牌 2：...
（列出 5-10 个主要品牌/型号）

【收集信息】对每个产品收集：
发布日期、价格、核心技术参数（重量/芯片/显示/电池/摄像头/AI 能力）、核心卖点、
市场表现/销量数据

【输出格式】
1. 产品对比表（markdown 表格：品牌 | 型号 | 发布时间 | 价格 | 重量 | 芯片 | ... | 亮点 | 不足）
2. 子品类市场概况（50-100 字）

请用中文输出。尽可能搜索最新数据。
```

### Agent 3：产业链 + 趋势分析师

```
【任务】<行业名>全品类调研 - Part N：产业链 + 市场趋势 + 未来预判

【产业链上游 - 关键环节】
1. 芯片平台：主流方案、国产替代进展
2. 显示/光学：技术路线（标注各路线优劣）
3. 传感器与摄像头
4. 电池/电源
5. 代工厂商

【市场规模与预测】
- 全球/中国出货量（近 3 年 + 未来 3-5 年预测）
- 细分品类占比变化
- 关键增长驱动因素

【关键趋势】
- 技术路线收敛判断
- 重量/续航/算力的三角平衡
- 端侧 AI 芯片演进
- 大厂入局影响
- 创业公司格局变化

【输出格式】
1. 产业链结构图（文字描述各层级 + 关键玩家）
2. 市场规模数据表格
3. 技术路线收敛趋势分析
4. 未来 2-3 年预判（5-8 个关键判断）

请用中文输出。尽可能搜索最新数据、研报摘要。
```

### Hermes 汇编要点

1. 交叉验证重叠数据点（如出货量数字冲突 → 标注 range）
2. REPORT.md 结构：执行摘要→赛道A→赛道B→技术对比→产业链→市场预测→预判→风险→数据质量
3. 中间文档落盘：`01_<赛道A>.md` / `02_<赛道B>.md` / `03_产业链与趋势.md`
4. DRBCV 卡片：从报告中提取 5-8 张，type 用 discriminant/prediction/causal

## 模板 2：假设验证/历史比较调研（如「AI 泡沫→应用」假设验证）

### Agent 1：历史周期比较

```
【核心任务】历史技术革命 S 曲线比较——验证「泡沫破裂→应用爆发」规律

分析 N 个历史技术革命周期，每个都要回答：
1. 泡沫期特征（什么被高估？标志性事件？何时破裂？）
2. 泡沫破裂后发生了什么（应用阶段何时到来？哪些行业意外爆发？）
3. 从泡沫顶点到应用爆发的时间间隔
4. 哪些投资标的在泡沫期被高估却在应用期兑现了价值？

【必须分析的周期】
① <周期1名称>（约 <年份范围>）
② <周期2名称>（约 <年份范围>）
...

【反例要求】
至少分析 2-3 个「泡沫破裂后什么都没有发生」的反例（如 3D 打印 2013、VR 2016）。
总结成功泡沫 vs 失败泡沫的判断框架。

【输出要求】
1. 每个周期的详细时间线（关键事件+年份）
2. 统一对比框架表
3. 共性规律总结（3-5 条）
4. 成功/失败判断框架

请用中文输出，注重数据准确性。
```

### Agent 2：当前周期映射

```
【核心任务】将当前 <技术浪潮名> 映射到历史周期，验证用户假设

用户假设：
「<复制用户的完整假设>」

【请分析以下维度】
1. 当前处于什么阶段？（类比历史上哪个时间点？泡沫标志有哪些？）
2. 基础设施过度建设会带来什么遗产？
3. 应用阶段哪些领域最可能爆发？（逐个分析用户提到的领域）
4. 泡沫会以什么方式破裂？（触发因素预测）

【输出格式】
1. 当前阶段定位（类比历史周期）
2. 各应用领域深度分析（支撑证据 + 风险）
3. 泡沫破裂情景预测
4. 5-8 个关键判断

请用中文输出。
```

### Agent 3：投资标的分析（如需）

```
【核心任务】<技术浪潮名> 应用阶段投资标的分析

用户计划定投的方向：
1. <方向1>
2. <方向2>
3. <方向3>

【请分析】
1. 每个方向的可投标的（含当前估值分位、增长逻辑、风险）
2. 应用阶段的投资时间线
3. 定投方案建议（比例+节奏+关键信号）
4. 逻辑证伪条件

尽可能查找最新估值数据和行业报告。使用东方财富 API / 蛋卷基金 API 获取实时数据。

请用中文输出。
```

### Hermes 汇编要点

1. 按「假设回顾→历史验证→当前定位→方向分析→投资方案→证据清单」结构
2. 对用户的原始假设逐层判决：方向对不对、时间线需不需要修正、排序需不需要调整
3. 每个方向的估值数据必须来自 L2 API，标注获取时间
4. 定投方案必须包含逻辑证伪条件
