# 科技产业链深度调研 — 输出结构与方法论

> 适用场景：用户要求调研某个科技赛道的产业链、技术趋势、市场规模、未来预判（非股票投资，无估值/仓位建议）。
> 与主 SKILL.md 的 REPORT.md 格式互斥：主模板用于 A 股投资决策，本模板用于纯行业/技术研究。

---

## 报告输出结构（5 段式）

### 一、产业链结构图

```
┌─────────────────────────────────────────────┐
│              产业链全景（ASCII 框图）          │
│  【上游 — 核心元器件与材料】                    │
│  芯片平台 / 显示面板 / 光学模组 / 传感器 / 电池  │
│  【中游 — 整机设计与制造/ODM/OEM】              │
│  方案设计 / 代工制造 / 品牌厂商                 │
│  【下游 — 渠道与应用生态】                      │
│  消费渠道 / 行业应用 / 内容/开发者              │
└─────────────────────────────────────────────┘
```

**每个环节需覆盖：**
- 关键玩家表格（厂商 + 定位 + 代表产品 + 客户）
- 技术路线对比（至少 3 条路线）
- 关键判断（1-2 句话）

### 二、市场规模数据

**至少 3 张表：**
1. **出货量预测表**（全球 + 中国，至少覆盖 3 年历史 + 5 年预测）
2. **市场收入规模表**（亿美元，含 YoY 增速）
3. **细分品类占比变化表**（各子品类出货占比演进）

### 三、技术趋势分析

**覆盖维度：**
- 技术路线收敛判断（哪条路线将胜出，为什么）
- 关键性能指标的演进曲线（如重量/续航/算力三角）
- 技术瓶颈与突破时间线（3-5 年 roadmap）
- 专利/并购动态

### 四、未来预判（6-8 个关键判断）

**每个判断格式：**
```
### 判断 N：<标题>
- <核心论点>
- <支撑证据/数据>
- <风险/不确定性>
```

**覆盖方向：**
- 品类演化（如 AI 眼镜 vs AR 眼镜谁主沉浮）
- 竞争格局（大厂入局影响、创业公司分化）
- 技术突破节点（如 MicroLED 量产时间）
- 供应链格局（代工厂话语权变化）
- 生态/平台层面（如 AI 大模型+眼镜的结合）
- 并购/整合趋势

### 五、数据可靠性说明

```
| 数据类型 | 可靠度 | 说明 |
|---------|--------|------|
| 具体数据来源 | 高/中高/中/中低 | 简要说明依据 |
```

## 研究方法论（3 Agent 并行 + Hermes 汇编）

### 阶段 1：并行分派 3 个 Agent

使用 `delegate_task` 同时分派三个 Agent，每个负责一个独立维度。详细任务模板见 `references/mode-b-agent-templates.md`。

**Agent 1 + 2**：各负责一个产品赛道，输出结构化对比表 + 市场概况。
**Agent 3**：产业链 + 市场规模 + 技术趋势 + 未来预判。

> 不搜索（Hermes 自搜）→ 不用 Agent Kanban → 直接用 `delegate_task(tasks=[...])`，3 个 Agent 并行，约 8-12 分钟返回。

### 阶段 2：Hermes 汇编（Agent 全部返回后）

1. **交叉验证**：三个 Agent 的重叠数据点有冲突 → 标注 range，不伪造一致性
2. **合并 REPORT.md**：执行摘要→赛道A→赛道B→技术对比→产业链→预测→预判→风险→数据质量
3. **中间文档落盘**：三个 Agent 原始输出保存为 `01_xxx.md` / `02_xxx.md` / `03_xxx.md`
4. **DRBCV 知识卡片**：从 REPORT.md 提取 5-8 张卡片存入 `cards/`，格式见 `references/drbcv-card-fix-pattern.md`

### 阶段 3：搜索受阻时的回退策略（Agent 端）

Agent 的搜索在中国网络下经常超时，会回退到训练知识撰写，自动标注 `[待验证]`。

Hermes 验收时：检查 `[待验证]` 标记数量（>10 处 → 标记「需二次验证」），在 REPORT.md 添加「数据可靠性说明」。

## 与主模板（A 股投资报告）的差异

| 维度 | 本模板（科技产业链） | 主模板（A 股投资） |
|------|-------------------|-------------------|
| 目标 | 理解行业，预判趋势 | 判断买入/持有/卖出 |
| 是否需要实时行情 API | 否 | 是（L2 必须） |
| 是否需要估值分析 | 否 | 是（PE/PB 分位） |
| 是否需要操作建议 | 否 | 是（仓位/定投节奏） |
| 数据可靠度要求 | 中（训练知识可接受） | 高（L2 API 必须） |
| 执行模式 | delegate_task 3 Agent 并行 | Kanban 多 Agent 调度 |
| 中间文档 | 3 份 Agent 原始输出落盘 | vb-librarian 合并 |
| 知识卡片 | Hermes 汇编后主动创建 5-8 张 | vb-librarian 负责 |

## 示例：智能眼镜产业链调研

核心结构：
1. 产业链五层拆解（芯片/显示/光学/传感器/电池 → 代工 → 品牌 → 渠道 → 应用）
2. 三张规模表（出货量 2021-2030E + 收入规模 + 品类占比演变）
3. 四条技术趋势（光学收敛 / 显示演进 / 重量续航算力三角 / 端侧 AI 芯片）
4. 八个预判（AI 眼镜超越 AR / 多模态 AI 标配 / 苹果分水岭 / 光学路线 2026-27 收敛 / 手机厂商入局 / 创业公司分化 / 大模型+眼镜场景 / 中国供应链受益）
5. 数据可靠性说明表

> 网络搜索阻断时（国内环境常见），按上述「阶段 2」回退策略：快速试探后转向训练知识撰写，在报告中逐项标注数据可靠度。

### 变体：产品全品类对比表

当用户要求输出「产品对比表」「全品类对比」「横评」「各品牌PK」时，在产业链报告之外需增加产品级对比表。格式见 `references/product-comparison-table-format.md`，关键分组：
- **表 1**：Birdbath 投屏类（XREAL / Rokid / 雷鸟 / VITURE / 华为 / TCL）
- **表 2**：光波导一体机（雷鸟 X2 / INMO / Snap / Meta Orion）
- **表 3**：企业级（Magic Leap / HoloLens）
